# aadd

組込み製品の機能仕様書の更新検討を支援するローカル Web アプリです。
変更要求の整理、対象仕様書の選定、修正文・差分の生成（Application 1〜3）を実装しています。

## セットアップ

- Python 3.13 以上、uv が必要です。
- 内製ライブラリ exmgai が `../exmgai` に存在する構成を前提にしています。
- KB は既存の kb-mcp の HTTP API を利用します。連携先リポジトリの変更は不要です。

```powershell
uv sync
```

`config.toml.example` を参考に `config.toml`、`env.toml.example` を参考に `env.toml` を用意します。
対象コントローラーの役割は、`target_roles.md.example` を参考に `target_roles.md` へ記述します。
実設定・役割記述の実体・`data/` は Git 管理対象外です。設定なしでも画面は起動しますが、AI 処理は実行できません。
AI のモデル名はアプリ設定と exmgai 設定で一致させてください。

| 設定 | 内容 |
| --- | --- |
| `ai_config` | exmgai の設定ファイル。生成モデルと Microsoft-Decision-1 の接続を定義 |
| `target_roles_file` | 対象コントローラーの役割 Markdown。既定 `target_roles.md` |
| `generation_model` / `decision_model` | exmgai の `models.name`。判断モデルの provider は `foundry` |
| `kb_url` / `kb_headers` | KB の URL と必要に応じた認証ヘッダー |
| `scope_paths` / `exclude_paths` | 検索対象・除外パス |
| `candidate_limit` | 変更ごとの検索候補数。既定5件 |
| `necessity_threshold` | 必要性判定のしきい値。既定0.5を超えた候補だけ選定 |
| `timeout_seconds` / `retry_count` / `concurrency` | 外部呼出しの制限。既定180秒・再試行1回・候補評価の同時実行2件 |
| `data_dir` | SQLite・添付原本の保存先。既定 `data/` |

設定内の相対パスはアプリ設定ファイルのあるフォルダーを基準とします。
`AADD_CONFIG` 環境変数でアプリ設定のパスを指定できます。
保存先を変更する場合は、そのフォルダーも Git 管理対象外にしてください。
設定を変更した場合はサーバーを再起動してください。

### 対象コントローラーの役割

```powershell
Copy-Item target_roles.md.example target_roles.md
```

サンプルには装置のシーケンス制御、レシピ管理、計測・補正、GUI、工場ホスト連携、保守、システム管理の役割を記載しています。
役割記述の実体は、実際に変更開発を行うコントローラーの責務に合わせて編集してください。
別の場所に置く場合は `target_roles_file` を変更します。相対パスはアプリ設定ファイルのあるフォルダーを基準とし、
変更先の実ファイルも Git 管理対象外にしてください。

変更内容の抽出時に役割ファイルを毎回 UTF-8 で読み込み、要求文・添付と分離して AI に渡します。
抽出プロンプトは、この責務に関係する変更だけを対象とし、範囲外のコントローラーやユニット内部の変更は含めないよう指示します。
役割の一覧そのものを変更要求と見なしたり、要求にない下位ユニットの仕様を推測して追加しないようにしています。
責務との関係が不明な点は不明点として残します。
対象スコープの変更がなければ空の結果として表示し、修正案作成には進みません。
既存の抽出結果は自動では変わりません。役割記述を設定・変更した後は、案件の変更内容を再抽出してください。
役割ファイルが未配置・空・読取り不能の場合は、無制限の抽出へ戻さずエラーにします。
役割記述も AI の文字数・トークン上限の検査対象で、設定した AI サービスへ送信されます。

## 起動

```powershell
uv run python -m uvicorn aadd.main:app --reload --host 127.0.0.1 --port 8001
```

http://127.0.0.1:8001 を開きます。ポートが使用中なら `--port` を変更します。
単一プロセス専用です。`--workers` による複数プロセス起動は行わないでください。
認証機能は含まれないため、ローカル利用を前提にループバックアドレスへバインドしてください。

## 操作

1. 変更要求を入力し、必要な資料を添付して「変更内容を抽出」を実行します。
2. 変更前・変更後・出典・不明点を確認し、項目を編集・追加・削除します。
3. 「確定して修正案を作成」で、検索・必要性判断・修正案生成を自動実行します。
4. 対象仕様書ごとの原文・修正文・差分、変更ごとの候補と必要性を確認します。
5. 修正文・差分をダウンロードできます。KB や元仕様書は更新しません。

同じ仕様書に関係する変更は、まとめて1件の修正案に反映します。
判断 AI には候補 Markdown の全文を渡し、`NoulAnswer.noul` の必要性確率を比較します。
同点時は検索関連度、文書IDの順で選びます。検索関連度を必要性確率の代わりには使いません。
差分は AI の出力ではなく、原文・修正文から Python で計算します。

候補なし、全件不要、取得・評価の一部失敗、不正な生成結果は「要確認」とします。
評価不完了の変更を除外して、その変更の最上位候補を決めることはありません。
他の変更について完成した修正案は保持します。

## 保存・再開

- 案件履歴、変更内容の版、候補・判定、原文スナップショット、修正案を SQLite に保存します。
- 添付原本は元ファイル名をパスに使わず、ランダムIDでローカル保存します。
- 再起動後は実行中だった処理を「中断」にし、画面から未完了工程を再実行できます。
- 再実行では、成功した取得・判断・修正案を再利用します。追加の変更が同じ仕様書に集まった場合は再生成します。
- 変更項目を保存すると版を更新します。過去の結果は履歴として表示し、古い版の実行は再開できません。
- 実行中は同一案件の編集・削除・二重開始を禁止します。
- 案件削除で関連する保存データと添付を削除します。バックアップはサーバー停止中に保存領域全体を対象にしてください。

自動的な処理再開や、外部 AI 呼出しの厳密な一回実行は保証しません。
外部呼出し後・保存前に停止した場合は、再実行で再課金される可能性があります。

## 添付と入力制限

| 形式 | 抽出対象 |
| --- | --- |
| `.docx` | 本文段落・表 |
| `.xlsx` | シート名・セル位置・値・数式と取得可能な保存済み計算値。再計算は行わない |
| `.pptx` | スライドのテキスト・表 |
| `.pdf` | テキストとページ番号 |
| `.txt` / `.md` | UTF-8 テキスト |

既定では添付10件、1件10MiB、Office の展開後50MiB、Excel の走査範囲20万セル、
入力と抽出テキストの合計12万文字、仕様書1件12万文字を上限とします。
モデルのコンテキスト・出力予約分と `max_input_tokens`（既定5万）の双方で AI 入力を制限します。
トークン計数には `o200k_base` を使い、安全余裕を設けます。モデルごとに上限を調整してください。
上限超過時に黙って切り詰めることはありません。

画像だけの PDF、OCR、図形・画像・埋め込み資料、旧 Office 形式は対象外です。
暗号化・破損・空の資料はエラーにします。マクロを含む Office 資料は拒否し、マクロは実行しません。
資料や仕様書の内容は exmgai で設定した AI サービスへ送信されるため、利用する環境の情報管理規定を確認してください。
画面では Markdown をソーステキストとして表示し、含まれる HTML は実行しません。

## 検証

```powershell
uv run python -m pytest -q
uv run python -m flake8 src tests --max-line-length=120
node --check src/aadd/static/app.js
```

テストは一時領域と代替 AI・KB / モック HTTP を使い、資格情報や実サービスへの接続を必要としません。
ブラウザ結合確認用のサーバーもテスト内に用意しています（実 AI は使いません）。

```powershell
uv run python -m uvicorn test_api:browser_app --app-dir tests --factory --host 127.0.0.1 --port 8002
```

実接続確認では、設定した KB の `POST /api/search_documents` と `POST /api/download_document`、
生成 AI、Microsoft-Decision-1 を使い、既知の要求・Markdown で結果を確認してください。
実装時点では実サービスへの接続は未検証です。

## 構成

- `src/aadd/main.py` / `api.py`: FastAPI、静的配信、案件・実行・成果物 API。
- `models.py` / `storage.py`: 入出力、版管理、SQLite と工程チェックポイント。
- `attachments.py`: Office・PDF・テキスト抽出と入力制限。
- `ai.py` / `knowledge_base.py`: exmgai と読取り専用 KB HTTP API。
- `workflow.py`: 抽出、自動選定、文書単位生成、差分、再実行。
- `static/`: フレームワークを使わない HTML/CSS/JavaScript。
- `memo/`: 実装計画と結果。

Lucide 0.468.0 をローカル同梱しています。配布元は `https://unpkg.com/lucide@0.468.0/dist/umd/lucide.min.js`、
ライセンスは `src/aadd/static/vendor/LICENSE.lucide` にあります。
