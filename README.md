# aadd

組込み製品の機能仕様書の更新検討を支援するローカル Web アプリです。
変更要求の整理、対象仕様書の選定、修正文・差分の生成（Application 1〜3）を実装しています。

## セットアップ

- Python 3.13 以上、uv、Git が必要です。
- 内製ライブラリ exmgai は GitHub リポジトリ `https://github.com/tomotaka-nagano/exmgai` の
  `v0.0.10` タグから取得します。ローカルへの事前配置は不要ですが、非公開リポジトリを読み取れる Git 認証が必要です。
- KB は既存の kb-mcp の MCP（Streamable HTTP）を利用します。連携先リポジトリの変更は不要です。
- マスク／アンマスクには別途起動した data-redactor の HTTP API を必ず利用します。

```powershell
uv sync
```

exmgai 0.0.10 では、Entra ID 認証による非同期 LLM 呼出し時の TypeError が修正されています。
依存環境の更新は `uv sync` を実行し、起動中のアプリを再起動してください。
exmgai の参照タグを更新する場合は、`pyproject.toml` の `tool.uv.sources` を変更して
`uv lock` と `uv sync` を実行します。`uv.lock` に取得元のコミットが記録されます。
アプリ終了時は実行中タスクを停止してから、生成・判断用クライアントの `close()` を呼び出します。
ライブラリが保持する HTTP 接続・非同期資格情報を解放し、終了処理の失敗は例外として通知します。

`config.toml.example` を参考に `config.toml`、`env.toml.example` を参考に `env.toml` を用意します。
対象コントローラーの役割は、`target_roles.md.example` を参考に `target_roles.md` へ記述します。
実設定・役割記述の実体・`data/` は Git 管理対象外です。設定なしでも画面は起動しますが、AI 処理は実行できません。
AI のモデル名はアプリ設定と exmgai 設定で一致させてください。

| 設定 | 内容 |
| --- | --- |
| `ai_config` | exmgai の設定ファイル。生成モデルと Microsoft-Decision-1 の接続を定義 |
| `target_roles_file` | 対象コントローラーの役割 Markdown。既定 `target_roles.md` |
| `generation_model` / `decision_model` | exmgai の `models.name`。判断モデルの provider は `foundry` |
| `kb_url` / `kb_headers` | KB の MCP エンドポイント（既定 `http://127.0.0.1:8000/mcp`）と必要に応じた認証ヘッダー |
| `redactor_url` / `redactor_headers` | data-redactor API の URL（既定 `http://127.0.0.1:8509`）と必要に応じた認証ヘッダー |
| `redactor_detection` | 検出方法。`ner` / `llm` / `both`（既定 `both`） |
| `redactor_mask_level` | 自動マスクの下限。`certain` / `strong` / `medium` / `weak` / `faint`（既定 `strong`） |
| `scope_paths` / `exclude_paths` | 検索対象・除外パス |
| `candidate_limit` | 変更ごとの検索候補数。既定5件 |
| `refinement_max_rounds` | 要求整理の最大ラウンド数。既定3回 |
| `refinement_documents_per_round` | 要求整理の1ラウンドあたりの仕様書取得上限。既定2件 |
| `refinement_max_documents` | 要求整理の1実行あたりの仕様書取得上限。既定6件 |
| `necessity_threshold` | 必要性判定のしきい値。既定0.5を超えた候補だけ選定 |
| `timeout_seconds` / `retry_count` / `concurrency` | 外部呼出しの制限。既定180秒・再試行1回・候補評価の同時実行2件 |
| `data_dir` | SQLite・添付原本の保存先。既定 `data/` |

設定内の相対パスはアプリ設定ファイルのあるフォルダーを基準とします。
`AADD_CONFIG` 環境変数でアプリ設定のパスを指定できます。
保存先を変更する場合は、そのフォルダーも Git 管理対象外にしてください。
設定を変更した場合はサーバーを再起動してください。

### ナレッジベースへの接続

kb-mcp は REST API ではなく MCP ツールを公開しています。
kb-mcp 側を Streamable HTTP で起動し、`kb_url` に `/mcp` を含むエンドポイントを設定してください。
stdio や旧 SSE トランスポート（`/sse`）には接続しません。

```powershell
uv run kb-mcp-server --transport http --host 127.0.0.1 --port 8000
```

上記は kb-mcp のリポジトリで実行します。既にサーバーが起動している場合、再起動は不要です。
既存設定との互換性のため、`http://127.0.0.1:8000` のようなホスト URL は `/mcp` を補完します。
リバースプロキシ配下では `https://example.test/kb/mcp` のように完全なエンドポイントを指定します。

公式 Python MCP SDK でセッションを初期化し、`search_documents` と `download_document` を呼び出します。
原文はリソースのチャンク再構成ではなく、`download_document` で取得します。
検索フィルター、Markdown の限定・重複排除、原文ハッシュ、タイムアウト・再試行は維持します。
呼出しごとにセッションを開閉するため、再試行時も新しいセッションで接続します。

### 対象コントローラーの役割

```powershell
Copy-Item target_roles.md.example target_roles.md
```

サンプルには装置のシーケンス制御、レシピ管理、計測・補正、GUI、工場ホスト連携、保守、システム管理の役割を記載しています。
役割記述の実体は、実際に変更開発を行うコントローラーの責務に合わせて編集してください。
別の場所に置く場合は `target_roles_file` を変更します。相対パスはアプリ設定ファイルのあるフォルダーを基準とし、
変更先の実ファイルも Git 管理対象外にしてください。

変更内容の抽出時に役割ファイルを毎回 UTF-8 で読み込み、要求文・添付と分離して AI に渡します。
抽出プロンプトは、この責務に関係する変更だけを対象とし、範囲外のコントローラーやユニット内部の変更は含めないよう指示します。
役割の一覧そのものを変更要求と見なしたり、要求にない下位ユニットの仕様を推測して追加しないようにしています。
責務との関係が不明な点は不明点として残します。
対象スコープの変更がなければ空の結果として表示し、修正案作成には進みません。
既存の抽出結果は自動では変わりません。役割記述を設定・変更した後は、案件の変更内容を再抽出してください。
役割ファイルが未配置・空・読取り不能の場合は、無制限の抽出へ戻さずエラーにします。
役割記述も AI の文字数・トークン上限の検査対象で、マスク API による処理後に AI サービスへ送信されます。

### AI 送信時のマスク／アンマスク

data-redactor の接続先を `redactor_url` に設定してください。
接続先が異なる環境では、Git 管理対象外の `config.toml` で変更します。
API 呼出しには `timeout_seconds` と `retry_count` を適用します。

- 変更内容の抽出・修正案の生成では、入力の全文字列値（要求文、役割記述、添付のファイル名・本文、
  変更内容、仕様書など）と指示文をまとめて `POST /mask` に渡します。
  共通の対応表で同じ表記を同じ置換語にし、生成 AI にはマスク後の値だけを送ります。
- 生成 AI の構造化応答は、文字列値ごとに `POST /unmask` へ送り、同じ対応表で復元してから返却・保存します。
  引用符・改行を含む元の表記も JSON の構造を壊さず復元します。
- Microsoft-Decision-1 の必要性判断でも、変更内容・候補仕様書・判断の指示文をまとめてマスクします。
  返ってくる必要性確率はアンマスクしません。
- 対応表は呼出しごとのメモリー内で扱い、AI やブラウザーへ送信せず、アプリの保存データにも追加しません。
- API の接続失敗・不正な応答時はエラーで停止します。未マスクでの AI 呼出しや、
  復元に失敗した置換語のままの結果返却へはフォールバックしません。
  入力トークン数はマスク前後の両方で検査し、切り詰めません。

検出範囲は data-redactor の辞書・検出設定に依存し、すべての機密情報の検出を保証するものではありません。
既定の `strong` は `certain` と `strong` の候補をマスクし、それ未満の候補は自動マスクしません。
アプリに候補の手動レビュー機能はないため、必要に応じて下限を下げ、サーバー側の辞書も整備してください。
`both` / `llm` はマスクサーバー側で検出用 LLM の準備・認証が必要です。
検出用 LLM は原文を受け取るため、機密情報を入力してよい接続先に限定してください。
生成 AI と判断モデルに送る内容はすべてマスキング API を通します。仕様書は Markdown 全文を1文書ずつ
単独でマスクし、変更要求などを別にマスクした結果と組み合わせます。要求整理にはマスク後の抜粋、
必要性判断と修正案生成にはマスク済みの全文を使います。伏せ字の対応表はモデルに送信しません。
同じ仕様書は1回の実行内でマスク結果を共有し、別の実行ではマスキング API 側の検出キャッシュを使います。
AADD は対応表を永続化せず、マスクに失敗した入力をそのままモデルに送ることはありません。
要求整理で KB に送る検索語は短い機能用語に限定し、マスク対象に該当する語が検出されたクエリは送信しません。
後続工程の KB 検索とローカル保存は従来どおりです。

#### 抽出前にマスク後の文字列を確認する

変更要求の入力画面で、要求文・添付を入力して「マスクのみ実行・確認」を押すと、
抽出用 LLM を呼ばずにマスク後の要求文と添付を表示します。
役割記述、システム指示、送信メッセージ全体（JSON）、応答スキーマも展開して確認できます。
生成 AI の接続設定は不要ですが、役割記述ファイルとマスク API の設定・起動は必要です。
マスクサーバー側の設定が `both` / `llm` の場合は、この操作でも検出用 LLM を利用します。

この操作だけでは案件・添付原本・プレビュー・対応表をアプリの保存領域に保存せず、
変更内容の抽出や判断モデルの呼出しも行いません。保存済み案件でも既存の変更内容や実行履歴は更新しません。
プレビューを表示した後も、未保存の要求文・添付は編集できます。入力を変えるとプレビューは消えます。
プレビューの失敗時は画面にエラーを表示し、抽出へは自動で進みません。

確認後に「変更内容を抽出」を押してください。
プレビューは初回入力のみの確認用で、KB 検索や後続ラウンドの動的な入力は含みません。
抽出実行時は同じ処理で改めてマスクします。
プレビュー結果を承認済み入力として固定する機能ではないため、
入力・役割記述・辞書・検出結果の変化によって実際の送信内容が変わる場合があります。

## 起動

```powershell
uv run python -m uvicorn aadd.main:app --reload --host 127.0.0.1 --port 8001
```

http://127.0.0.1:8001 を開きます。ポートが使用中なら `--port` を変更します。
単一プロセス専用です。`--workers` による複数プロセス起動は行わないでください。
認証機能は含まれないため、ローカル利用を前提にループバックアドレスへバインドしてください。

## 操作

1. 変更要求を入力し、必要な資料を添付します。必要に応じて「マスクのみ実行・確認」で内容を確認してから、
   「変更内容を抽出」を実行します。
2. 初稿を作成し、既存仕様の確認が必要な場合は KB-MCP で検索・取得して推敲します。設定を省略すると
   最大3ラウンド、仕様書取得は1ラウンドあたり最大2件、1実行あたり最大6件です。取得に失敗した文書も
   上限に数えます。設定値は1以上の整数で、変更後はバックエンドを再起動してください。
   1ラウンドの検索は最大2クエリのままです。既存仕様は変更前の挙動や責務の裏付けに使い、
   変更後は要求と添付を根拠にします。未確認事項があれば理由付きで暫定表示します。
   変更前・変更後・出典・不明点を確認し、項目を編集・追加・削除します。
3. 「確定して修正案を作成」で、要求整理とは独立して、検索・必要性判断・修正案生成を自動実行します。
4. 対象仕様書ごとの原文・修正文・差分、変更ごとの候補と必要性を確認します。
5. 修正文・差分をダウンロードできます。KB や元仕様書は更新しません。

同じ仕様書に関係する変更は、まとめて1件の修正案に反映します。
判断 AI には候補 Markdown の全文を渡し、`NoulAnswer.noul` の必要性確率を比較します。
同点時は検索関連度、文書IDの順で選びます。検索関連度を必要性確率の代わりには使いません。
差分は AI の出力ではなく、原文・修正文から Python で計算します。

### モデルの推定利用額

`env.toml` の各 `[[models]]` に、契約の単価を **USD／100万トークン**で設定できます（`env.toml.example` 参照）。
生成 AI は `input_token_cost` と `output_token_cost`、Decision-1 は `input_token_cost` を使用します。
バックエンドは抽出・修正案生成の各実行が終わった時点で、標準出力に `model_usage` の JSON を1行出します。
ログには実行 ID、試行番号、呼び出し回数・トークン数・判明分の `estimated_usd`、単価や使用量の不足で
全額を計上できなかった呼び出し数（`unpriced_calls`）が含まれます。進捗確認では再出力しません。
見積もりは請求額ではなく、マスキング API 内部の検出用 LLM は含みません。

候補なし、全件不要、取得・評価の一部失敗、不正な生成結果は「要確認」とします。
評価不完了の変更を除外して、その変更の最上位候補を決めることはありません。
他の変更について完成した修正案は保持します。

## 保存・再開

- 案件履歴、変更内容の版、候補・判定、原文スナップショット、修正案を SQLite に保存します。
- 添付原本は元ファイル名をパスに使わず、ランダムIDでローカル保存します。
- 再起動後は実行中だった処理を「中断」にし、画面から未完了工程を再実行できます。
- 再実行では、成功した取得・判断・修正案を再利用します。追加の変更が同じ仕様書に集まった場合は再生成します。
- 変更項目を保存すると版を更新します。過去の結果は履歴として表示し、古い版の実行は再開できません。
- 実行中は同一案件の編集・削除・二重開始を禁止します。
- 案件削除で関連する保存データと添付を削除します。バックアップはサーバー停止中に保存領域全体を対象にしてください。

自動的な処理再開や、外部 AI 呼出しの厳密な一回実行は保証しません。
外部呼出し後・保存前に停止した場合は、再実行で再課金される可能性があります。

## 添付と入力制限

| 形式 | 抽出対象 |
| --- | --- |
| `.docx` | 本文段落・表 |
| `.xlsx` | シート名・セル位置・値・数式と取得可能な保存済み計算値。再計算は行わない |
| `.pptx` | スライドのテキスト・表 |
| `.pdf` | テキストとページ番号 |
| `.txt` / `.md` | UTF-8 テキスト |

既定では添付10件、1件10MiB、Office の展開後50MiB、Excel の走査範囲20万セル、
入力と抽出テキストの合計12万文字、仕様書1件12万文字を上限とします。
モデルのコンテキスト・出力予約分と `max_input_tokens`（既定5万）の双方で AI 入力を制限します。
トークン計数には `o200k_base` を使い、安全余裕を設けます。モデルごとに上限を調整してください。
上限超過時に黙って切り詰めることはありません。

画像だけの PDF、OCR、図形・画像・埋め込み資料、旧 Office 形式は対象外です。
暗号化・破損・空の資料はエラーにします。マクロを含む Office 資料は拒否し、マクロは実行しません。
資料や仕様書の原文はマスク API に、マスク後の内容は exmgai で設定した AI サービスへ送信されます。
利用する環境の情報管理規定を確認してください。
画面では Markdown をソーステキストとして表示し、含まれる HTML は実行しません。

## 検証

```powershell
uv run python -m pytest -q
uv run python -m flake8 src tests --max-line-length=120
node --check src/aadd/static/app.js
```

テストは一時領域と代替 AI・KB / マスク API のモック HTTP を使い、資格情報や実サービスへの接続を必要としません。
ブラウザ結合確認用のサーバーもテスト内に用意しています（実 AI は使いません）。

```powershell
uv run python -m uvicorn test_api:browser_app --app-dir tests --factory --host 127.0.0.1 --port 8002
```

実接続確認では、設定した KB の MCP エンドポイント経由で `search_documents` と `download_document`、
マスク API の `POST /mask` と `POST /unmask`、生成 AI、Microsoft-Decision-1 を使い、
既知の要求・Markdown で結果を確認してください。
実装時点では実サービスへの接続は未検証です。

## 構成

- `src/aadd/main.py` / `api.py`: FastAPI、静的配信、案件・実行・成果物 API。
- `models.py` / `storage.py`: 入出力、版管理、SQLite と工程チェックポイント。
- `attachments.py`: Office・PDF・テキスト抽出と入力制限。
- `ai.py` / `knowledge_base.py`: exmgai と読取り専用 KB HTTP API。
- `redactor.py`: data-redactor HTTP API、入力のマスクと構造化応答の文字列値の復元。
- `workflow.py`: 抽出、自動選定、文書単位生成、差分、再実行。
- `static/`: フレームワークを使わない HTML/CSS/JavaScript。
- `memo/`: 実装計画と結果。

Lucide 0.468.0 をローカル同梱しています。配布元は `https://unpkg.com/lucide@0.468.0/dist/umd/lucide.min.js`、
ライセンスは `src/aadd/static/vendor/LICENSE.lucide` にあります。

## 対象外

Application 4〜7（インターフェース影響分析、充足確認と反復探索、最終承認・更新レポート）、
元仕様書や KB への書き戻し、認証・複数ユーザー運用は実装していません。
