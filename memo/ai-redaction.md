# AI 送信時のマスク／アンマスク

## 計画

- data-redactor の README と HTTP API ガイド、既存の AI 呼出し経路を確認する。
- 抽出・生成・判断のすべてで送信前にマスクし、生成応答だけをアンマスクする。
- 接続先・検出方法・マスク下限を設定に追加し、実設定は Git 管理外のままとする。
- HTTP モックで機密情報の送信防止、復元、障害時の停止、既存動作を検証する。

## 実装

- 入力の文字列値と指示文を `/mask` の複数パートで一括処理する。
  JSON のキーや構造は保持し、共通の対応表で入力間の置換語を統一する。
- 生成応答は文字列値ごとに `/unmask` へ渡して復元し、復元後もモデルのスキーマで検証する。
  元の名称に引用符・改行・バックスラッシュが含まれても JSON の構造は壊さない。
- 判断モデルにはマスク後の状態・指示を渡し、確率は復元しない。
- 対応表は呼出し内だけに保持する。マスク失敗時の未処理送信や復元失敗時の結果返却は禁止する。
- API の型・パート ID と順序を検証し、既存のタイムアウト・再試行・エラー通知の仕組みを使う。
- 既定値は API と同じ `both` / `strong`。検出漏れの可能性と検出用 LLM への原文送信を README に記載する。

## 検証

- モック HTTP で抽出・生成・判断経路を検証する。実サービスへ機密情報を送る検証は実施しない。
- `uv run python -m pytest -q`: 全82件成功。
- `uv run python -m flake8 src tests --max-line-length=120`: 成功。
- Pylance: AI とマスククライアントの診断・構文エラーなし。
- マスク API のオプション・対応表保持、不正な応答の拒否、タイムアウト・再試行、
  全経路の未マスク送信防止、復元失敗時の停止、JSON の特殊文字の復元を確認した。
- マスク後のトークン上限超過時もモデルを呼ばないこと、並行処理で対応表が混ざらないことを確認した。
- 既存の変更抽出・必要性評価・生成・ワークフロー・API・保存の回帰テストも成功した。
