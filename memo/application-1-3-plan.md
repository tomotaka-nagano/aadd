# Application 1〜3 実装計画

## 範囲
- 変更要求と .docx/.xlsx/.pptx/.pdf/.txt/.md を入力し、変更前後を AI 抽出する。
- ユーザーが抽出結果を編集・確定した後、KB 検索、Decision-1 の必要性判断、最上位仕様書の修正案生成を自動実行する。
- 同じ仕様書に関係する変更を集約し、原文・修正文・プログラムで計算した差分を表示する。
- SQLite とローカルファイルで保存し、中断した工程を再実行できるようにする。
- 影響分析、充足確認ループ、最終承認レポート、KB 書き戻し、旧 Office、OCR は対象外。

## 手順
1. uv/FastAPI の基盤、設定サンプル、外部 API 契約テスト。
2. 添付抽出、SQLite 保存、変更抽出・編集 UI。
3. KB 検索・全文取得、Decision-1 の必要性判断、自動選定。
4. 文書単位の修正生成、差分、進捗、履歴と再実行。
5. 単体/API/ブラウザ検証、README と実装結果記録。

## 守る条件
- AI 呼出しは exmgai のみを経由し、KB は HTTP API で読取り専用にする。
- Decision 回答の型をインストール済み SDK で確認してからランキングを実装する。
- 候補の評価が不完了、候補なし、全件不要の場合は黙って生成しない。
- 任意 HTML を実行せず、添付サイズ・展開サイズ・入力長を制限する。
- 実設定と案件データは Git 管理しない。単一プロセスで起動する。

## 検証
- 各実装単位で pytest。最後に全テスト、Flake8（120文字）、画面確認。
- 実 AI/KB 接続はローカル設定がある場合のみ行い、未検証をモック成功と区別して記録する。
