# 変更要求のマスクプレビュー

## 計画

- 最初の変更要求画面に、抽出用 LLM を呼ばないマスク専用ボタンと確認ビューを追加する。
- 入力組立て・マスク処理は通常の抽出と共通化し、要求文・添付・役割記述・指示を確認できるようにする。
- 新規入力は保存せず処理し、保存済み案件でも変更内容・履歴を更新しない。
- プレビューの内容は承認済み入力として固定しない。抽出時に再度マスクすることを明記する。

## 実装

- `/api/extraction-previews` は既存の添付抽出・入力制限を再利用し、未保存入力をプレビューする。
- `/api/projects/{project_id}/extraction-previews` は保存済み案件を処理する。
  存在・版・実行中状態を確認し、保存データは変更しない。
- 通常の抽出と共通の役割読込み・入力組立て・一括マスクを使用する。
  プレビューではモデルの生成・トークン予算検査・抽出・アンマスクは行わない。
  実際の送信時は従来どおりマスク前後の予算検査を実施する。
- プレビュー応答にはマスク後の送信メッセージ・システム指示・応答スキーマだけを含め、
  原文を含む対応表は返さない。
- 要求文・添付本文を読みやすく表示し、役割・指示・JSON・スキーマは展開式にする。
  HTML を含む入力も `textContent` で表示し、実行しない。
- 未保存入力や添付を変えたとき、案件を切り替えたとき、抽出を開始したときはプレビューを消す。
  処理中は入力・添付操作・抽出ボタンを無効化し、API 失敗時は既存の通知にエラーを表示する。
- マスク API が検出用 LLM を使う場合があること、抽出時には再度マスクすることを画面と README に明記する。
