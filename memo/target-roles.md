# 対象の役割に基づく変更抽出

## 計画
- 役割 Markdown のサンプルを `target_roles.md.example` として管理する。
- 実体 `target_roles.md` は Git 管理対象外にし、設定で読込み先を指定する。
- 抽出プロンプトに役割スコープを渡し、範囲外の変更・要求にない詳細を生成しないようにする。
- 役割記述がない・空・読取り不能の場合は AI に送信せず停止する。
- スコープ内の変更がない場合は空の抽出結果を許容し、画面でその旨を表示する。
- プロンプトと役割ファイルの受渡し、設定パス、異常時と空結果をテストする。

## 実装結果
- 提示された役割を `target_roles.md.example` に保存し、実体 `target_roles.md` を Git 除外に追加。
- `target_roles_file` 設定を追加。相対パスはアプリ設定の場所を基準に解決する。
- 抽出ごとに UTF-8 の役割記述を読み、`target_roles` として要求文・添付と分離して渡す。
- 範囲内のみ抽出、複合要求は責務部分のみ、役割からの変更創作・不要な詳細化を禁止する指示を追加。
- 役割ファイルの未配置・空・読取り不能・文字数上限超過時は AI 呼出し前に停止。
- 役割内容も既存の AI トークン予算検査に含まれる。
- 範囲内ゼロ件は正常な空結果として表示する。編集結果の確定・修正案生成は1件以上を必要とする。
- 既存の抽出結果は自動では変更しない。役割設定後に再抽出すると新しいスコープが適用される。
- 実役割ファイルは作成・コミットせず、環境別に用意する。README に準備方法を記載。

- 全テスト57件成功、Flake8（最大120文字）成功、変更ファイルのエディター診断エラーなし。
- `git check-ignore` で実体 `target_roles.md` だけが除外され、サンプル `.md.example` は除外されないことを確認。
- 実モデルによる意味的な抽出精度は未検証。テストではプロンプト、送信内容、異常時停止、空結果の制御を検証する。
